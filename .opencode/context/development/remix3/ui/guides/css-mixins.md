# Guide: CSS Mixins with Design Tokens

**Core Idea**: Use `css()` from `remix/ui` with design tokens for consistent, type-safe styling.

## Quick Start

```typescript
import { css } from 'remix/ui'
import * as t from '../ui/tokens.ts'

// Use precomputed mixins
<button mix={[t.buttonBase, t.buttonPrimary]}>Click</button>

// Create custom
const card = css({ ...t.cardBase, backgroundColor: t.colors.accentLight })
```

## Token Reference

| Category | Access | Example |
|----------|--------|---------|
| Colors | `t.colors.primary` | `'#0f172a'` |
| Spacing | `t.spacing[4]` | `'1rem'` |
| Font sizes | `t.fontSizes.md` | `'0.875rem'` |
| Borders | `t.borders.sm` | `'1px'` |

## Common Patterns

```typescript
// Button
const buttonPrimary = css({ ...t.buttonBase, backgroundColor: t.colors.accent })

// Input with focus
const inputStyle = css({ ...t.inputBase, '&:focus': { borderColor: t.colors.accent } })
```

## Best Practices

1. Use precomputed mixins (`t.buttonBase`, `t.inputBase`)
2. Prefer token values over hardcoded strings
3. Use spread to extend precomputed mixins

## Gotcha: Raw `var()` in `css()` Breaks Dark Mode (added 2026-05-06)

The `css()` function compiles `theme.*` tokens to `var(--rmx-*)` CSS variables. Writing raw `var()` strings bypasses this mapping — the variable name won't match the `--rmx-*` variables generated by `createTheme()`:

```typescript
// ❌ Wrong — variable name doesn't match theme contract
const card = css({ color: 'var(--text-primary, #0f172a)' })

// ✅ Correct — let css() handle the --rmx- prefix mapping
const card = css({ color: theme.colors.text.primary })
```

**Always use `theme.*` tokens inside `css()`**. The raw `var()` approach works with direct CSS but creates `--rmx-` prefixed variable names that don't match manual `var()` references, breaking dark mode.
