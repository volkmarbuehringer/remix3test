# Frame prefetching with a one-shot response cache

**Extracted:** 2026-10-23 · **Updated:** 2026-11-13 · **Pin:** remix 3.2.0 (preview release `v0.20261113.180701-main-b4a0aa9a` / source `b4a0aa9a`)
**Vendor:** `@remix-run/component/src/runtime/prefetch.ts` (`defaultPrefetch`, `createDefaultPrefetch`, `startPrefetching`, `startViewportPrefetching`, `getIntentAnchor`), `run.ts` (`prefetch` option), installed guide `node_modules/remix/guides/05-interactivity.md` §"Prefetch links before navigation".

## Why the default prefetcher is not enough here

- `app/assets/entry.tsx` replaces the runtime default with `run({ resolveFrame })`: every frame request adds `X-Remix-Frame`/`X-Remix-Target`, a one-shot `X-Agent-Prefill` payload, `cache: 'no-store'`, and the 4xx-renders / 5xx-`ErrorCard` / 401-redirect policy, then reconciles `X-Remix-Redirect-To` into `frame.src`.
- The stock default prefetcher (`createDefaultPrefetch`) fetches HTML on its own and discards it; the navigation resolves again, so the app pays a second SSR per hovered link. Its request also lacks the app's prefill and stores nothing a navigation can claim.
- **Since #12277 the strategy itself is extensible**, so the app no longer shadows it: `app/assets/frame-prefetch.browser.ts` calls `defaultPrefetch(src, options, { fetch, processFrame })` and keeps only the app policy. Remix owns request sharing/dedupe by source+target, cancellation when every caller is gone, same-origin/hash normalization, idle-deferred parsing, and the `X-Remix-Prefetch: true` GET.
- **Since #12249 the resolver delegates to `defaultResolveFrame`**, so request construction is shared too; see `frame-navigation.md`.

## Wiring

- `app/assets/frame-prefetch.browser.ts` — the one-shot cache:
  - `prefetchFrame(src, options)` is the `PrefetchFrame` hook and now a thin wrapper over `defaultPrefetch`. It forwards `options` unchanged (including the automatic trigger's `element` and the caller signal, so the vendor owns caller attribution and cancellation). Its `fetch` override adds `X-Agent-Prefill` + `cache: 'no-store'`, deletes `init.signal` (see below), classifies the response with `classifyFrameResponse(..., { mode: 'prefetch' })`, and stores a **clone** only when a real navigation would render it. The original goes back to the vendor parser.
  - `processFrame(_prefetchReferences, context)` ignores the vendor discovery and feeds the already-parsed `context.assets` into `prefetchFrameAssetElements`, so the HTML is parsed once. It only runs asset hints for responses this warm actually cached.
  - `claimPrefetchedFrame(url, target, signal)` returns a stored entry **or awaits the in-flight store** (not the vendor's idle parse), honoring the navigation signal. `takePrefetchedFrame` is the sync claim; `clearPrefetchedFrames()` bumps the generation and drops every entry.
  - Key is `target + ' ' + absolute href` with the hash stripped (the vendor fetch URL has no fragment); entries are single use, TTL 10 s, max 8, and consuming one clears the rest.
- `app/assets/frame-asset-prefetch.browser.ts` — `prefetchFrameAssetElements(elements, baseUrl)` is the production hint creator; `prefetchFrameAssets(response, sourceUrl)` is the standalone response-based path used by tests (and for the rare non-`ok` fragment, see below); `frameFragmentBaseUrl(fragment, responseUrl)` resolves the first `<base href>`. `clearPrefetchedAssets()` is the test-only pending-hint cleanup.
- `app/assets/frame-response.browser.tsx` — one navigation request path through `defaultResolveFrame`; `classifyFrameResponse` is total over the vendor's rejected responses and is reused by the prefetcher.
- `app/assets/entry.tsx` — `run({ prefetch })`; `resolveFrame` **awaits** `claimPrefetchedFrame` for a plain GET (method `get`/undefined, no `formData`), deletes the prefill entry on a hit, reconciles the redirect header for both cached and fetched responses, and only clears + fetches when the claim misses.

## Invariants

- **A prefetch must never navigate the document.** `classifyFrameResponse(..., { mode: 'prefetch' })` never yields a navigation action; redirect-with-`target`, 401, 5xx, and non-HTML bodies are simply not cached. Only navigation mode calls `window.location.assign`.
- **Never consume `agentPrefillMap` during a prefetch.** The warmed HTML already contains the prefilled content; deleting the one-shot entry would starve a later navigation that misses the cache. The hit path deletes it; the real fetch keeps deleting on `response.ok`.
- **A click that beats the warm must await it, not refetch.** The runtime starts the prefetch on `pointerdown`, tens of ms before the click navigation. `claimPrefetchedFrame` awaits the **store** promise (resolved in the `fetch` override as soon as the response is cached), not the whole `defaultPrefetch` promise, so it does not wait for the vendor's idle parse and asset discovery. `clearPrefetchedFrames()` only runs after the claim misses. Do not reorder this into a sync `take` + clear.
- **The prefetch caller's `options.signal` must not reach the shared fetch.** Since #12277 the hook receives a per-caller signal that aborts when the anchor loses eligibility or is removed — and for links inside the navigating frame (the appointment week arrows, `app/ui/appointment-sidebar.tsx`) the commit that consumes the warm is exactly what removes the anchor. Forwarding that signal to `fetch` errors the cached response body while the frame runtime is still reading it, which surfaces as the app's fatal `"signal is aborted without reason"` card after the URL has already advanced. `prefetchFrame` only checks `signal.aborted` before starting and deletes `init.signal` before the request; the shared request stays independent, mirroring the vendor default (abort only when every owner is gone; page unload cancels it). Guarded by `frame-prefetch.test.browser.ts` §"keeps a warmed response readable after its prefetch caller aborts".
- **An aborted caller must not populate the cache.** The `fetch` override checks the outer caller signal before storing; a caller that aborts while the response is in flight leaves no entry. Guarded by §"does not store a response for a caller that aborts before it arrives".
- **Only plain GETs are warmable.** Cache lookups are gated on `isPlainGet`; `frame.reload({ method, body })` POSTs and form-data GETs bypass the cache entirely (the key does not encode method or body). The prefetch hook itself is GET-only.
- **Safari traversal scroll with warmed frames.** Since #12274, when a traversal renders from content that is already available (including a response claimed from this cache), WebKit restores the destination scroll after the frames render instead of keeping the page-being-left's position. Warmed back/forward navigation therefore no longer lands at the wrong offset. The app's `scroll-restoration` e2e guards the window-scroll case; nested `[data-page-scroller]`/`[data-grid-scroll]` reset remains app-owned (`app/ui/page-scroll-reset.browser.tsx`).
- **5xx is never cached.** The recovery card is a client-side component, not a reusable fragment; 4xx validation fragments are cached because a real navigation renders them.
- **CSP nonces.** Frame fragments carry the nonce of the response that rendered them. Reuse is same-document and short-lived; the app's frame content has inert JSON scripts plus import maps that the runtime appends with the installed map's nonce. Do not introduce executable `nonce={getCspNonce()}` inline scripts into frame fragments — a warmed copy would carry a stale nonce.
- **Warm requests are `priority: 'low'` and `cache: 'no-store'`**, matching the old app warmer, so a hover warm does not compete with the navigation it accelerates and nothing lands in the HTTP cache; navigation requests keep the browser default. The vendor also sends `X-Remix-Prefetch: true`.
- **`rel=prefetch` is feature-gated per engine.** WebKit (Playwright 27.2) reports `link.relList.supports('prefetch') === false`, while Chromium and Firefox report `true`. `prefetchAsset()` skips hint creation on WebKit, so a warm still serves the frame HTML but destination assets start cold; do not remove the guard. The opt-in WebKit browser suite asserts the no-op path.
- **Asset hints are part of the warm.** `defaultPrefetch` parses the HTML once; `processFrame` passes its `context.assets` to `prefetchFrameAssetElements`, which honors `<base href>`, skips assets the document already has, dedupes by `href`/`as`/`crossorigin`/`integrity`/`referrerpolicy`, and removes each hint on `load`/`error`. Hints are independent of the one-shot HTML cache: `clearPrefetchedFrames()` does not remove them, because a destination entry module or stylesheet stays useful after the one-shot fragment is invalidated. Do not run scripts from the parsed HTML or inject its nonce-bearing nodes.
- **A 4xx fragment is cached but is not vendor-parsed with `ok`.** `defaultPrefetch` only calls `processFrame` for `ok` HTML, so the `fetch` override runs `prefetchFrameAssets(copy, url)` for a stored non-`ok` fragment — the old warmer discovered its assets too. Rare path; the fragment is parsed twice only there.
- **Targeted warms resolve against the most recent `run()`.** Since #12245 the named-frame registry is per runtime; the module-level `prefetch(href, { target })` lookup (`prefetch.ts` → `getNamedFrame`) reads the frames published by the most recently started `run()`. The app starts one runtime in `app/assets/entry.tsx`, so the target lookup is unaffected; a second `run()` in the same document would redirect targeted warms to its own frames.
- **Head reconciliation is not vendor-identical.** The app-owned hints are outside the vendor's internal `pendingPrefetchLinks` WeakSet, which `frame.ts`'s head diff preserves. A top-level frame navigation can therefore remove an in-flight app hint without firing `load`/`error`. `prefetchAsset()` treats a disconnected pending hint as stale and re-creates it, and a 15 s fallback timer clears a hint that never settles; without both, the pending promise would suppress that asset for the rest of the document's lifetime. (`prefetchFrameAssetElements` deliberately does **not** call the vendor's `prefetchReferences()`, which would register the hints in that WeakSet but drop the app's stale-hint rules.)
- **Viewport prefetch uses the same override.** `startPrefetching(signal, prefetch)` installs the app's hook and still starts `startViewportPrefetching()`; the observer calls the active `prefetchFrame`, so `data-rmx-prefetch="viewport"` warms through the app's one-shot cache. Since #12256 a link that enters view during a scroll — including in a nested scroller, because the listener is capturing on `document` — waits 150 ms after the last scroll and is prefetched only if still visible; links already in view without a scroll prefetch immediately. Since #12286 pending viewport warms pause while `document.hidden` and recheck intersections/eligibility on `visibilitychange`, and disposal clears the timer/queue. The vendor's idle-deferred parse now applies to the app hook too; the cache store still happens at the fetch, so a fast click is not delayed by it.

## Adoption points

Intent anchors: admin-lists filter tabs (Alle/Mit Elementen/Leer) and numbered page links, admin-users filter tabs, and the appointment-sidebar week arrows. Every admin/client grid pager's prev/next uses `data-rmx-prefetch="viewport"` — lists, users, appointments, messages, offerings, offering configs, resources, uploads, webhook requests, chatlog, and the clients grid. These links enter view only at the grid footer, so the runtime's scroll settle avoids warming links passed on the way; the numbered page links stay intent-only so a visible pager does not warm every page in its window. The runtime reads intent anchors **on the anchor itself** (`getIntentAnchor` → `a[href][data-rmx-prefetch="intent"]`) and viewport anchors through the observer's `getRequest` (`data-rmx-prefetch === 'viewport'`), so add the attribute per link. Prefer same-origin GET anchors that already carry `data-rmx-target`; skip `data-rmx-document` links (runtime filters them), downloads, and JS-triggered reloads (a reload with no anchor never prefetches). Do not mark grid rows or filter tabs viewport: they are visible on load, so each would start a full SSR warm immediately.

- `app/assets/frame-prefetch.test.browser.ts` — single use, concurrent dedupe, in-flight claim (one request), abort-while-waiting, target keying, cross-origin skip, sibling invalidation, refused responses, plus the vendor request policy (`X-Remix-Prefetch`, low priority, no-store, prefill header), 4xx caching/readability, clone-vs-original, the aborted-in-flight regression, and the non-cacheable 5xx/401/non-HTML matrix.
- `app/assets/frame-asset-prefetch.test.browser.ts` — scripts/styles/modulepreloads/image/font preloads, `<base>` resolution, nested templates, document dedupe, `imagesrcset`/media skips, non-HTML/partial responses, re-creation after a disconnected hint, and the `prefetchFrame()` wiring. Uses a `MutationObserver` plus a bounded `waitFor` poll because hints disappear on the first 404; do not assert on the live DOM after a fixed sleep.
- `app/actions/admin/admin-lists-prefetch.test.e2e.ts` — the real runtime. Intent: hover the marked "Leer" tab, assert one fragment request, click, assert the count stays 1 and the URL moves to `status=empty`. Viewport: seed 11 lists under a unique filter, open the filtered grid, scroll the pager's "Nächste Seite" link into view, assert one fragment request, click, assert the URL moves to `offset=10` and the count stays 1. Both pass on Chromium and Firefox.
- `app/actions/client/clients-prefetch.test.e2e.ts` — the separate `app/actions/client/grid-page.tsx` pager against the seeded 200 clients: scroll "Weiter" into view, assert one fragment request, click, assert `offset=15` and the count stays 1. Passes on Chromium and Firefox.
- Attach the request listener and `waitForRequest` **before** `goto` in both e2e tests: a pager already in view prefetches on load, so attaching after the grid appears misses the warm. Match on path + `offset` + `x-remix-frame: true`, then assert the count is still 1 after the click.
- `app/assets/frame-asset-prefetch.test.browser.ts` § WebKit — when `relList.supports('prefetch')` is false, the suite awaits `prefetchFrameAssets()` and asserts zero hint elements; the hint-shape assertions remain on Chromium/Firefox.
- `app/assets/frame-response.test.browser.ts` § `classifyFrameResponse` — the prefetch-mode decisions (5xx/401/redirect/non-HTML yield no cacheable render, 4xx HTML renders) and the navigation-mode policy; prefill is consumed only on a navigation.
