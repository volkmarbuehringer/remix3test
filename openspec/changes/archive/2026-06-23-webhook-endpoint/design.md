## Context

The app needs a webhook endpoint that external services can call with a token. Payloads are stored in a new table and viewed through an SSR page with live updates via SSE. The app already uses PostgreSQL (raw SQL via `pool.query`) and has a data-table layer — no new dependencies needed.

## Goals / Non-Goals

**Goals:**

- Token-authenticated JSON POST endpoint that stores arbitrary JSON payloads
- UUID-based table with JSONB column for the payload
- SSR viewer page with paging, sorting, and filtering on the stored data
- SSE endpoint that notifies the viewer page of new entries after insertion
- Token validated against a configurable secret (env var or DB-stored)

**Non-Goals:**

- No authentication dashboard (tokens are static for now)
- No payload schema validation (stored as-is)
- No rate limiting (separate concern)

## Decisions

- **Raw SQL over data-table**: The `remix/data-table` layer is used for the app's main CRUD tables, but for a simple insert+query table, raw SQL via `pool.query` is simpler and avoids data-table's column type overhead for UUID/JSONB.
- **UUID primary key with DB default**: Column uses `UUID` type with `DEFAULT gen_random_uuid()`. The ID is generated by PostgreSQL at insert time, not by the application. The INSERT statement uses `RETURNING id` to get the generated value back. This ensures consistent UUID generation and avoids JS-side UUID library dependencies.
- **Token via env var**: A single `WEBHOOK_TOKEN` env var validated on every request. Simple and sufficient for the initial use case.
- **SSE over polling**: Native `EventSource` on the client connected to a Remix GET route that streams events. After each successful POST, the endpoint notifies the SSE channel. Simpler than WebSocket for one-directional push.
- **SSE channel via in-memory event emitter**: A simple Node `EventEmitter` shared between the POST handler and the SSE route. No Redis or external pub/sub needed for a single-process app.

## Risks / Trade-offs

- [In-memory SSE channel] SSE notifications are lost if the process restarts. Mitigation: the viewer page can have a manual refresh button; SSE is a convenience, not a guarantee.
- [No payload validation] Malformed or huge payloads are stored as-is. Mitigation: set a reasonable request body size limit via `createRequestListener` or middleware.
- [Single token] All callers share one token. Mitigation: extensible to per-source tokens later.
